# 项目治理 Backlog

本仓库由「小概率匹配平台 (主线)」与「钱途工具 (独立上线业务)」并存。为了确保后续开发的高效推进与系统稳定性，将后续开发和治理任务划分为以下四个阶段。

---

## 📅 Now：P1 Smoke Test 问题修复 (当前重点)

该阶段的任务是当前正在执行的生产环境冒烟测试与安全校验发现的问题，属于紧急且必须立即修复的任务。

*   **P1.1 生产环境配置校验与修复**
    *   **描述**：针对正在执行的生产冒烟测试，分析 Vercel Production Logs。如果发现微信登录、短信发送、支付回调等功能因生产环境变量配置缺失或配置格式错误导致 `500` 错误，需立即配合发布人补充并校对生产环境变量。
    *   **目标**：确保线上所有主路径（登录、充值、解锁、发信）均不报 5xx 错误。
*   **P1.2 Supabase RLS (Row Level Security) 误伤修复**
    *   **描述**：针对在生产环境真实访问中暴露的 RLS 权限拦截问题进行修复。重点校验非 Service Role 的普通登录用户与匿名用户对 `public_profiles`、`projects`、`unlocks` 表的读取限制。若发生合法读写报 `403 Forbidden`，需立刻限缩或订正 RLS SQL 策略，并在 staging 验证后推向 production。
*   **P1.3 支付回调通知异常紧急补救**
    *   **描述**：如果在冒烟测试中发现微信支付回调接口（`/api/payment/notify`）校验签名失败，或因网络抖动导致订单状态未正确流转，需即刻编写修补脚本，提供管理员后台的手动单笔核销/对账入口，防范资金客诉风险。

## 📅 Next：P2 SEO 基础优化 (近期计划)

该阶段任务主要为针对小概率匹配平台 Web 端进行的搜索引擎抓取和流量引入的基础改造。

*   **P2.1 真实 NuxtLink 链接重构**
    *   **描述**：将前台公开的卡片组件（例如 `ProjectCard.vue`、`DeveloperCard.vue`）中使用的 `@click` 编程式路由跳转方式重构为真实的 `<NuxtLink>` 标签。
    *   **目标**：使搜索引擎爬虫能够顺着 `href` 路径（如 `/projects/123`，`/developers/abc`）爬取详情页面，同时维持原有的 UI 视觉与 hover 特效。
*   **P2.2 项目 Slug 路由引入**
    *   **描述**：使用具有语义化的拼音或英文短横线 Slug（如 `/projects/python-developer-hangzhou`）代替纯数值自增 ID（如 `/projects/12`），优化 URL 的友好度。
    *   **目标**：在 `projects` 数据表中引入 `slug` 唯一索引字段，重构 Nuxt 3 动态路由，并在后端接口层实现根据 Slug 查询项目。
*   **P2.3 Sitemap 自动更新与 Canonical Link 配置**
    *   **描述**：动态生成 XML 格式的站点地图（Sitemap），包含所有已审核的项目和公开的开发者 Profile，并在 SSR 详情页的 `<head>` 区域自动注入 `<link rel="canonical" href="...">`，以防搜索引擎因带参数的动态 URL 判定重复内容。
*   **P2.4 Schema.org 结构化数据接入**
    *   **描述**：在项目详情页和开发者详情页中利用 JSON-LD 注入结构化数据（如 `JobPosting`、`ProfilePage`、`Article` 等）。
    *   **目标**：使小概率匹配平台在 Google、百度等搜索引擎结果页（SERP）中能呈现富媒体卡片展示（Rich Snippets），提高点击率。
*   **P2.5 百度收录与内容策略部署**
    *   **描述**：接入百度主动推送（实时）API，当新项目或开发者注册公开后自动发起推送；在 Nuxt 3 前端路由守卫中精准上报百度统计 PV/UV，并制定针对防爬机制与爬虫白名单的抓取方案。

## 📅 Later：中远期规划 (待后续独立端规划/非当前任务)

该阶段包含移动端独立部署与非紧急的裂变/增值运营性需求。

*   **L.1 Flutter App 真实凭证配置与商店上架**
    *   **描述**：由于 `mirauni_app` 当前仅完成了基础 UI 架构开发，后续需填补真实的微信 App 登录凭证、微信 App 支付商户信息、极光推送 JPush AppKey 及各种 iOS/Android 签名配置。
    *   **目标**：在真机环境调通全部业务流，并通过 iOS App Store 和 Android 应用市场（华为、应用宝、小米）的隐私安全合规审核上架。
*   **L.2 项目付费置顶与推荐位曝光**
    *   **描述**：为项目方提供增值付费工具。项目方可额外扣除额度或通过支付购买“首页置顶卡片”或“高亮推荐标签”，实现更高频的开发者曝光。
*   **L.3 开发者与项目方合作互评系统**
    *   **描述**：在开发者与项目方通过解锁取得联系、甚至确认合作后，提供多维度的评分与文字互评机制。
    *   **目标**：沉淀平台真实合作信用，降低冷启动时期的虚假项目和欺诈风险。
*   **L.4 邀请裂变激励机制**
    *   **描述**：构建“老带新”邀请机制。开发者或项目方通过专属分享链接邀请新用户注册并完善资料后，双方可免费获赠 2-5 次的联系方式解锁额度，加速平台用户裂变。

## 📅 Experimental：长期与实验性探索 (非当前任务)

该阶段涉及具有高度不确定性、需要复杂架构重构或尚无清晰商业闭环的实验性需求。

*   **E.1 基于代币或自治权重的 DAO 社区风控治理**
    *   **描述**：当平台用户达到一定体量时，引入社区自治机制。对于恶意项目方（如虚假项目、只白嫖方案不招人）或恶劣开发者（接单后失联、技术作假），由社区核心成员组成 DAO 进行仲裁投票，实施降权、封禁或扣除平台信誉分。
*   **E.2 钱途 RAG 路径推荐框架兼容性重构与接入**
    *   **描述**：针对早期钱途 RAG 方案（`docs/RAG.md`、`RAG-HANDOFF.md`）中的 UUID 数据库类型冲突设计缺陷进行底层逻辑重写。在确认钱途工具的商业模式可并入匹配平台后，将这一早期的知识库推荐算法重构成向前兼容的数据模型，为独立开发者提供高阶智能合伙匹配和路径推荐。
