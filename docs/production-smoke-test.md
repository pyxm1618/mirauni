# P1 生产环境冒烟测试指南 (docs/production-smoke-test.md)

> 本文档用于规范小概率匹配平台的上线验收与生产冒烟测试流程（P1 级标准），确保在不修改或篡改生产数据、不泄露任何系统凭证的前提下，快速、稳定地完成上线验证。

## 1. 自动化只读冒烟测试

我们提供了一个独立的 Node.js 自动化脚本 [smoke-test.js](file:///Users/pyxm1618/Documents/mirauni/scripts/smoke-test.js)，用于在上线后对公开只读端点进行健康性探测。

### 1.1 安全规则与设计
- **生产拦截保护**：当 `TARGET_URL` 包含生产域名 `mirauni.com` 时，脚本**必须**检测到环境变量 `ENABLE_PRODUCTION_SMOKE=true` 才会执行。若未配置，脚本将打印安全拦截提示，并调用 `process.exit(1)` 非零状态码强行退出，防止在 CI 中误触发生产测试。
- **公开只读限制**：测试端点完全限定在公开、只读的接口。严禁测试登录、发送验证码、创建订单、解锁等写操作，以防污染线上真实业务数据。
- **免凭证设计**：整个脚本只检验 HTTP 状态码，绝不读取、不打印、不输出任何 Cookie、Token、数据库密码或第三方 API Secret。

### 1.2 默认测试端点
- `GET /` - 检查首页是否可正常访问（Nuxt 3 SSR）
- `GET /sitemap.xml` - 检查搜索引擎站点地图是否可加载
- `GET /api/projects` - 检查项目列表数据接口
- `GET /api/developers/search` - 检查开发者搜索接口
- `GET /api/articles` - 检查文章列表接口

### 1.3 可选 Telemetry 写入检查
若需要测试自建埋点接口（如测试 `POST /api/track` 在线写入），该接口不是纯只读，它会写入 `events` 物理表。测试需满足以下硬性条件：
1. 显式设置环境变量 `INCLUDE_TRACK=true`。
2. 若 `TARGET_URL` 指向生产环境，必须同时显式设置 `ENABLE_PRODUCTION_SMOKE=true`。
3. 埋点载荷中的 `event_name` 统一使用 `ci_smoke_test`，方便过滤和归档。

### 1.4 执行方法

#### A. 本地/测试环境冒烟（默认）
```bash
# 默认请求 http://localhost:3000
node scripts/smoke-test.js

# 指定 Staging/本地自定义端口测试
TARGET_URL=http://localhost:3000 node scripts/smoke-test.js
```

#### B. 生产环境只读冒烟（需授权）
```bash
# 必须显式传入 ENABLE_PRODUCTION_SMOKE=true 允许生产测试
TARGET_URL=https://mirauni.com ENABLE_PRODUCTION_SMOKE=true node scripts/smoke-test.js
```

#### C. 包含 Telemetry 写入测试的冒烟（需授权）
```bash
# 本地或 Staging 运行
TARGET_URL=http://localhost:3000 INCLUDE_TRACK=true node scripts/smoke-test.js

# 生产环境运行 (必须两项配置同时为 true)
TARGET_URL=https://mirauni.com ENABLE_PRODUCTION_SMOKE=true INCLUDE_TRACK=true node scripts/smoke-test.js
```

## 2. 核心功能手动冒烟流程

对于由于安全隔离而无法自动化校验的敏感写操作、交互行为，须由测试负责人按照以下 P1 手动测试用例进行上线验收。

> [!CAUTION]
> 在生产环境进行手动测试时，请务必使用**测试账号**（例如已指定的内部测试手机号），且充值步骤仅检验收银台拉起或沙箱支付参数的生成，切勿发生实际的资金扣减，除非在执行特许真实支付验证。

### 2.1 Web 前台与核心业务流验证

| 序号 | 验证模块 | 操作步骤 | 预期结果 |
| :--- | :--- | :--- | :--- |
| 1 | **用户登录 (SMS)** | 1. 访问 `/login` 页面。<br>2. 输入测试手机号，点击获取验证码。<br>3. 在本地测试环境查看控制台打印的验证码（生产环境在手机上接收短信）。<br>4. 填入验证码，点击登录。 | 登录成功，页面重定向到主页，导航栏显示用户头像/手机号。 |
| 2 | **个人资料编辑** | 1. 进入「我的 / 个人资料」页面。<br>2. 修改昵称、签名或技能标签，点击保存。 | 保存成功，刷新页面后修改后的内容依然正确显示。 |
| 3 | **次数包充值页面** | 1. 访问充值/解锁套餐定义页面。<br>2. 验证 30/50/100 元等套餐价格及赠送方案正常渲染。 | 页面结构和价格展示无误。如果是开发/测试环境，点击支付应能调用后台生成预支付参数（拉起微信二维码或 JSAPI 支付参数）。 |
| 4 | **联系方式解锁** | 1. 访问 `/projects` 列表页，任选一个项目进入详情页。<br>2. 点击「解锁联系方式」按钮。 | 扣减余额成功，页面无缝展示真实的联系人微信/手机号，且重复点击不再重复扣次数。 |
| 5 | **实时站内信** | 1. 在解锁后的项目/开发者页面中点击「发送消息」。<br>2. 输入测试消息并发送。<br>3. 登录接收方的账号，进入消息列表。 | 接收方可实时（Realtime）接收到新消息通知，且可顺畅回复，状态为已读。 |

### 2.2 管理后台 (mirauni-admin) 验证

| 序号 | 验证模块 | 操作步骤 | 预期结果 |
| :--- | :--- | :--- | :--- |
| 1 | **后台登录** | 1. 打开管理后台（`admin.mirauni.com` 或本地 `localhost:5173`）。<br>2. 使用管理员账号与密码登录。 | 校验 JWT 通过，成功跳转进入后台主仪表盘页面。 |
| 2 | **数据仪表盘** | 进入后台首页。 | 仪表盘各项指标（活跃用户数、新项目数、订单流水等）无报错加载。 |
| 3 | **项目审核** | 1. 寻找一条待审核的项目记录。<br>2. 点击「审核通过」或「驳回」。 | 操作成功，该项目在 Web 前台的可见性状态实时发生改变。 |
| 4 | **订单与埋点分析** | 1. 切换至订单管理列表。<br>2. 切换至分析看板、事件明细。 | 列表能正常加载分页数据，埋点趋势图渲染正常，无 500 或 RLS violation 报错。 |

## 3. Flutter 移动端手动验证流程

由于 Flutter 构建在主 Actions 链路中耗时较长，目前 Flutter 的质量保障为**非阻断式**。但在客户端发版或发布测试包前，开发者必须进行如下本地及真机手动验证：

### 3.1 静态与测试验证
在移动端目录中手动执行本地检查：
```bash
cd mirauni_app
# 1. 依赖完整性安装
flutter pub get
# 2. 静态分析（确保没有严重语法及规范警告）
flutter analyze
# 3. 运行单元和组件测试
flutter test
```

### 3.2 运行与功能点走查
测试人员需在 iOS/Android 真机或模拟器上启动 App，手动走查：
1. **启动与导航**：启动页 (Splash) 顺利跳转至主导航页面（Shell），下方的项目、开发者、消息、我的 Tab 切换顺滑无白屏。
2. **手机号登录**：点击登录拉起验证码输入框，输入验证码能成功进入 App 内页。
3. **充值与解锁**：拉起充值套餐列表，点击充值能够唤起微信支付 SDK（取决于证书配置），在已解锁项目详情中能正常显示隐藏的微信号。
4. **推送通知**：App 退至后台时，使用测试工具发送一条测试站内信，确认系统通知栏能够实时拉起极光推送的消息。

## 4. 事故应对与安全红线

> [!CAUTION]
> 1. **严禁在公开日志或文档中附带真实的秘钥信息**（包括但不限于 `SUPABASE_SERVICE_KEY`、`JWT_SECRET`、微信 API 密钥等）。
> 2. **手动操作生产数据库时**（比如为了冒烟测试修改个别状态），必须由具备 DBA 或项目负责人权限的人员执行，并做好事务提交。
> 3. 如果在冒烟测试中发现重大 Bug（如充值失败、数据泄露、页面 500），请立刻启动 [回滚程序](./deployment-runbook.md#5-回滚步骤)。
